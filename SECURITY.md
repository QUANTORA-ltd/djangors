# Security Policy

## Supported Versions

Starting with `1.0.0`, security fixes are backported to the current minor release line.

| Version | Supported |
| ------- | --------- |
| `1.x`   | Yes       |
| `< 1.0` | No        |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, please report them privately via one of the following channels:

1. **GitHub Security Advisories** (preferred): open a private advisory at
   `https://github.com/QUANTORA-ltd/djangors/security/advisories/new`.
2. **Email**: send details to `security@quantora.dev` (or `chidiisking7@gmail.com`) with the
   subject `[SECURITY] djangors: <short summary>`.

Please include:
- The affected crate(s) and version (`djangors` workspace version).
- A clear description of the vulnerability and its impact.
- Reproduction steps or a minimal proof-of-concept.
- Any suggested mitigation or patch, if you have one.

## Response Timeline

- **Acknowledgement**: within 48 hours.
- **Triage & Assessment**: within 5 business days.
- **Fix & Coordinated Disclosure**: we will work with you on a fix, release a patched version
  to crates.io, and credit you in the security advisory and `CHANGELOG.md` (unless you prefer
  to remain anonymous).
